# تطبيق فهيم لأندرويد

يحتوي مجلد `android` على تطبيق Android أصلي خفيف يعرض واجهة فهيم الحالية من خدمة Render القائمة. لا تُنسخ الواجهة إلى مشروع منفصل ولا يُنشأ خادم بديل: التطبيق يفتح الموقع وواجهات API من الأصل نفسه، لذلك تبقى مسارات المصادقة والجلسات وسجل المحادثات ولوحة الإدارة والبث المباشر كما هي، دون إعداد CORS أو كشف مفاتيح الخادم داخل APK.

عنوان الخدمة الذي تم التحقق منه:

- التطبيق وواجهات API: `https://chat-boot-d9hz.onrender.com`
- لوحة Render: `https://dashboard.render.com/web/srv-d07shg15pdvs73afhpkg`

## فتح المشروع وبناؤه

1. ثبّت Android Studio مع Android SDK Platform 36 وBuild Tools، وJDK 17.
2. افتح مجلد `android` في Android Studio وانتظر مزامنة Gradle.
3. شغّل التطبيق على جهاز أو محاكي متصل بالإنترنت باستخدام إعداد `debug`.
4. لإنشاء APK للاختبار من Android Studio اختر **Build > Build APK(s)**. يظهر الملف عادةً في `android/app/build/outputs/apk/debug/app-debug.apk`.
5. لإنشاء AAB للنشر، اختر **Build > Generate Signed Bundle / APK > Android App Bundle**، ثم استخدم مفتاح توقيع إصدار محفوظًا خارج المستودع وفي مكان آمن. لا ترفع ملف المفتاح أو كلمة مروره إلى Git.

يمكن البناء من PowerShell بعد تثبيت JDK 17 وAndroid SDK:

```powershell
cd android
.\gradlew.bat assembleDebug
.\gradlew.bat bundleRelease
```

يتطلب بناء `bundleRelease` إعداد مفتاح توقيع إصدار قبل النشر إلى Google Play. لا يحتوي المستودع على مفتاح توقيع.

## عنوان الموقع وواجهات API

تُضبط الخدمة مركزيًا في `android/app/build.gradle` عبر الخاصية `faheemServerUrl`، والقيمة الافتراضية هي عنوان Render أعلاه. جميع استدعاءات `/api/...`، بما فيها تدفق المحادثة، تستخدم نطاق الصفحة نفسه؛ لا تُغيّر المسارات ولا تُنشأ مفاتيح Gemini أو بيانات قاعدة البيانات في التطبيق.

لاستهداف نطاق HTTPS آخر عند الحاجة، مرّر الخاصية نفسها إلى Gradle:

```powershell
.\gradlew.bat assembleDebug "-PfaheemServerUrl=https://your-existing-render-service.onrender.com"
```

تُرفض عناوين HTTP أو العناوين التي تحتوي مسارًا أو بيانات اعتماد. لا تغيّر عنوان الخدمة لمجرد اختبار محلي، ولا تنقل قاعدة البيانات أو تضف خادمًا بديلًا. تحديث الموقع أو إعداداته على Render يبقي التطبيق متصلًا به ما دام النطاق ثابتًا.

## سلوك Android

- اسم الحزمة الثابت: `com.faheem.education`، والاسم الظاهر: «فهيم».
- يستخدم التطبيق شعار المدرسة الموجود في `public/school-logo.png` للأيقونة وشاشة البداية.
- يعتمد على HTTPS وشهادات Android الموثوقة، ويرفض HTTP المختلط ولا يتجاوز أخطاء TLS.
- يحتفظ WebView بجلسات الموقع وتفضيلاته، مع تعطيل النسخ الاحتياطي لبيانات التطبيق.
- يدعم الرجوع داخل سجل WebView، واختيار الصور والملفات من منتقي Android دون طلب صلاحية تخزين عامة، وتغيير حجم العرض عند ظهور لوحة المفاتيح.
- يعرض شاشة عربية قابلة لإعادة المحاولة بدل صفحة WebView فارغة عند تعذر تحميل الصفحة.
- لا يطلب التطبيق صلاحية الميكروفون أو الكاميرا. الإملاء الصوتي يعتمد على دعم WebView لواجهة `SpeechRecognition` الموجودة في الموقع.

## تحديث التطبيق مستقبلًا

1. حدّث الموقع والخادم المعتادين على Render؛ لا تعدّل قاعدة Neon أو مفاتيح Gemini لهذا الغرض.
2. إذا بقي نطاق الخدمة كما هو، فلن تحتاج إلى تغيير عنوان التطبيق.
3. ارفع `versionCode` و`versionName` في `android/app/build.gradle` قبل إصدار جديد.
4. أنشئ AAB موقّعًا باستخدام مفتاح الإصدار الأصلي نفسه، ثم ارفعه إلى Google Play. احتفظ بنسخة احتياطية آمنة من المفتاح.
5. لا تضع أسرار الخادم أو ملفات التوقيع أو بيانات مستخدمين حقيقية في المستودع.
6. أزيلت قيمة كلمة مرور SMTP التي كانت موجودة في ملف الإعدادات النموذجي؛ إذا كانت قيمة فعالة، دوّرها وأزلها من سجل Git وفق إجراءات إدارة الأسرار لديكم.

اسم الحزمة مضبوط إلى `com.faheem.education`. لم يتوفر حساب Google Play Console للتحقق من حجز الاسم؛ أكّد توفره في Play Console قبل النشر.

## التحقق

تم بناء APK من نوع Debug والتحقق من ملفه وبيانات الحزمة. الملف الناتج محليًا هو `android/app/build/outputs/apk/debug/app-debug.apk`؛ ملفات البناء لا تُرفع إلى Git. لم يتوفر جهاز Android أو محاكي متصل، لذلك لم يُثبت التطبيق ولم تُختبر تفاعليًا تدفقات الدخول والتسجيل والمحادثات ورفع الصور والتنقل.

نجحت مجموعة اختبارات الخادم كاملة: 58 اختبارًا، دون فشل أو أخطاء. أُضيفت كذلك سجلات تشخيص آمنة لمسارات إعداد Gemini وأخطاء الاتصال وردود HTTP، واختبارات تتحقق من عدم تسجيل الأسرار أو البيانات الشخصية. التحقق من سجلات Render الإنتاجية بعد نشر التغييرات ما زال مطلوبًا لتحديد السبب الفعلي لأي عطل يحدث هناك.
